# Работа над проектом

Читайте [PRD](docs/prd.md) как требования к продукту, [SPEC](docs/spec.md) как технический контракт, [ТЗ по задачам](docs/backlog.md) и [спринты](docs/sprints.md) как план выполнения. [Исходное ТЗ v0.3](docs/technical-specification.md) сохранено для истории, [исследование](docs/research.md) — датированный контекст. Документы не подтверждают работоспособность импорта.

- Пишите собственную реализацию на Python без зависимости от Java или кода Investbook. Используйте `GPL-3.0-or-later` для исходного кода; до включения стороннего кода проверяйте совместимость лицензии.
- Не добавляйте в Git настоящие брокерские отчёты, персональные данные, базы, ключи и пароли. Для публичных тестов используйте синтетические данные.
- Сначала подтвердите форматы на образцах Сбера и Альфы. Не объявляйте импорт готовым, пока операции, позиции и денежные остатки не сверены с итогами брокера. Неизвестные строки показывайте явно.
- Учитывайте перекрывающиеся отчётные периоды и повторную загрузку. Операции должны иметь связь с исходным файлом и строкой.
- Финансовые расчёты выполняйте с десятичной арифметикой. Проверяйте FIFO и XIRR независимыми контрольными примерами и сравнивайте итоговые значения с отчётами.
- После каждого этапа отмечайте в README, что реализовано, что проверено и какие форматы отчётов ещё не поддержаны.
