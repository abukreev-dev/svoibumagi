# Свои бумаги — ТЗ по задачам V1

- **Статус:** план и критерии приёмки; часть компонентов реализована экспериментально, ни один спринт ещё не принят целиком
- **Основание:** [PRD](prd.md) → [SPEC](spec.md) → это ТЗ → [спринты](sprints.md)
- **Приоритеты:** P0 — нужен для достоверного учёта и следующего этапа; P1 — нужен для выпуска V1; P2 — улучшение после выпуска либо при наличии времени.

У каждой задачи ниже есть проверяемый результат. Для всех задач действует общее определение готовности: код и документация соответствуют SPEC, тесты используют синтетические данные, локальные реальные образцы не попадают в Git/CI, ошибки и неподдерживаемые случаи видны, README отмечает реализованное, проверенное и неподдерживаемые форматы. Готовность задачи адаптера не равна готовности всего импорта.

Критерии задач проверяются на согласованных старых и новых образцах, независимых расчётных примерах и чистой установке. Полную личную историю владелец загрузит повторно в рабочий сервис. Её неполнота в текущей контрольной базе требует статуса `unavailable` для портфельных показателей, но сама по себе не является невыполнением ТЗ сервиса.

## Порядок работы с изменениями

Если образцы не содержат нужных итогов или выявляют новый тип события, SB-02 фиксирует ограничение; соответствующий адаптер не получает статус «поддерживается», пока невозможно подтвердить полноту. Объём SB-07/SB-08 определяется фактически найденными вариантами. Каждое расширение формата получает отдельное ТЗ по шаблону: сигнатура, классификация строк, контрольные итоги, ограничения, синтетический тест.
