# Приёмка V1: проверяемые барьеры

**Дата среза:** 10 октября 2026 года. **Решение:** SB-20 остаётся `partial`; действующий сервис размещён, исходный репозиторий не публиковался.

После исходного среза личный сервис и публичный информационный лендинг размещены на `https://svoibumagi.bukreev.pro/` с исходным коммитом `90d077e`. Это публикация действующего экземпляра, но ещё не публикация исходного кода как открытого репозитория. Docker-контейнер на `ddl` здоров; порт опубликован только на `127.0.0.1:18110`. Проверены HTTPS, защищённая сессия владельца, отказ 401 для закрытой операции без сессии, сохранение синтетического счёта после перезапуска и его удаление, пустая SQLite v20 (`quick_check=ok`, внешних ошибок 0), первая копия и пробное восстановление. Ночная копия настроена на 03:55 MSK; внешней копии пока нет. Соседний сайт после изменения nginx вернул 200. Полный пул отчётов владелец загрузит заново, поэтому серверный том намеренно пуст. Подробности — в [инструкции размещения](deploy-ddl.md).

Владелец уточнил границу приёмки: предоставленные старые и новые отчёты служат контрольным набором для сервиса; полный пул будет загружен заново в рабочем экземпляре. Ни 25 открытых интервалов текущей проверочной базы, ни спорный январский файл сами по себе не блокируют готовность механизма загрузки, если сервис явно оставляет показатели конкретного портфеля недоступными. Строки ниже про непрерывную историю, принадлежность и реальный FIFO/XIRR описывают отдельную приёмку пользовательских данных после полной загрузки. SB-20 остаётся частичным из-за оставшихся продуктовых и эксплуатационных проверок, а не из-за требования дозагрузить текущую базу.

Создан отдельный пустой локальный Docker-экземпляр на `http://127.0.0.1:18081` с собственным постоянным томом. Для него явно включён режим локального HTTP; обычный Compose сохраняет защищённые cookie для HTTPS. Проверены вход, создание синтетического счёта, сохранение после перезапуска и удаление проверочной записи. В конце база пуста (`accounts=0`, `source_files=0`), SQLite v20 прошла `quick_check` и проверку внешних ключей. База `data/` с прежним контролем не изменялась.

Отдельный временный Docker-проект проверил реальный HTTP-путь двух согласованных отчётов, по одному каждого брокера: загрузка, предпросмотр, подтверждение, 62 события по контрольным таблицам, повтор без добавления событий, четыре CSV, резервная копия и восстановление. После перезапуска сохранились два файла и 62 события; `quick_check` и внешние ключи прошли. Этот временный проект и его том удалены. Доказательство относится к выбранным образцам и не объявляет полную историю пользователя принятой.

Отдельный закрытый локальный кандидат исходного репозитория собран из текущего дерева с одним начальным коммитом. Дерево совпало с рабочим срезом; проверка отслеживаемых файлов не нашла известных идентификаторов закрытых отчётов или типовых признаков персональных данных. Исходный архив и wheel прошли аудит. Кандидат не опубликован; решение о правообладателе и остальные барьеры приёмки открыты. Число файлов меняется с каждым этапом и проверяется при пересборке.

Оценка двух синтетических счетов проверена отдельно: известная рублёвая стоимость остаётся подытогом при отсутствующей цене другой позиции, а CSV сохраняет статус `unavailable`. Пустой сервис явно сообщает об отсутствии проведённых отчётов без показа 0 ₽ как стоимости портфеля. Нулевая валютная позиция даёт нулевую стоимость без требования конвертации; ненулевой валютный остаток всё ещё блокирует полный расчёт. Этот контроль уточняет SB-15/SB-17, но не подтверждает доходность личного портфеля.

После исходного среза получены 10 уникальных месячных HTML Сбера. Расширенный закрытый реестр содержит 128 уникальных отчётов; прежние 118 сохранили экономический контроль, а новые 10 получили независимые контроли из исходных HTML. Все 128 прошли временный веб-прогон перекрытий. Разрывов периода стало 26; во всех крайние позиции и денежные остатки совпадают. Это не доказывает отсутствие операций внутри разрывов. Числа 38 и восемь изменившихся границ ниже описывают исходный срез до новых файлов.

Дополнительно 127 непротиворечивых уникальных файлов прошли совместный импорт в одну временную базу пяти счетов с проверкой конечных остатков, четырёх CSV, происхождения строк и восстановления. Одна спорная копия ИИС осталась в ожидающей попытке после блокировки межсчётного дубля. Общий расчёт по-прежнему недоступен; успешный технический импорт не подтверждает полноту истории.

В той же временной базе два подтверждённых владельцем месяца без операций закрыли только свои даты у одного обычного счёта Сбера; 1–2 ноября и разрывы остальных счетов остались открытыми. Записи сохранились после восстановления копии. Позднее оба подтверждения внесены в постоянную локальную базу. Это не подтверждение других календарных промежутков.

Дополнительный просмотр Intelinvest подтвердил выборочные отображаемые сделки и денежные строки Сбера по исходным HTML и показал разделение ИИС и обычного счёта в пользовательских портфелях. Он не устанавливает подлинный код договора в спорной копии ИИС и не закрывает разрывы истории. Точные значения остаются в закрытой заметке.

Отдельная временная проба одной базы провела пять представительных отчётов разных счетов и заблокировала шестую спорную копию ИИС без изменения журнала; резервная копия и восстановление прошли. Позднее в `data/` создана постоянная локальная база с 127 проведёнными отчётами по пяти счетам. Спорная попытка и созданный для неё пустой шестой счёт удалены после резервного копирования; исходный файл сохранён отдельно. В базе действуют два подтверждения месяцев без операций, но остаются 25 открытых интервалов. Приложение запущено на loopback; общий расчёт недоступен. Сквозная приёмка всей истории ещё не завершена.

Этот акт связывает критерии [PRD](prd.md), [SPEC](spec.md) и [ТЗ](backlog.md) с текущими доказательствами. Числа из настоящих отчётов, имена файлов и договоров находятся только в игнорируемом Git каталоге `private/`.
