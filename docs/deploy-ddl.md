# Размещение на ddl

Публичный адрес: `https://svoibumagi.bukreev.pro/`. Анонимному посетителю доступен только лендинг и форма входа. Все счета, исходные файлы, операции и выгрузки требуют пароль владельца. Текущий вариант — экспериментальный личный экземпляр; он не принимает регистрацию других пользователей.

Исходники размещены в `/home/www/svoibumagi.bukreev.pro`, Compose-проект `svoibumagi`, приложение слушает только `127.0.0.1:18110` через [оверлей](../deploy/compose.ddl.yaml). Системный nginx завершает TLS и проксирует HTTP в контейнер. В контейнере по умолчанию включены `Secure` и `HttpOnly` cookie. Автоматические запросы котировок MOEX ISS отключены. Данные лежат в именованном Docker-томе `svoibumagi_svoibumagi_data`; настоящие отчёты в исходный репозиторий не копируются.

Переменные в закрытом `.env` на сервере: `SVOIBUMAGI_PASSWORD_HASH` и `SVOIBUMAGI_MOEX_ISS_ENABLED=0`. Файл и каталог резервных копий доступны только владельцу сервера. Пароль в открытом виде не кладётся в Git и не передаётся в журналы. Входной файл ограничен 20 МБ, поэтому в nginx задан лимит 21 МБ.

Для обновления: перед переносом исходников сделать резервную копию командой `bash deploy/backup-ddl.sh`, затем перенести только отслеживаемые файлы, пересобрать образ `docker compose -f compose.yaml -f deploy/compose.ddl.yaml --env-file .env up -d --build`. После запуска проверить `https://svoibumagi.bukreev.pro/`, вход, закрытость `/operations`, состояние контейнера, SQLite `quick_check`, сертификат и соседний сайт. Не удалять именованный том.

Ночная копия создаётся [скриптом](../deploy/backup-ddl.sh) в `/home/www/svoibumagi.bukreev.pro/backups`. Скрипт проверяет целостность SQLite и исходных файлов через приложение, а затем структуру ZIP. Копии сейчас хранятся только на `ddl`; отдельного внешнего хранилища и автоматического удаления старых копий нет. Восстановление выполняется только в новый каталог по инструкции в [эксплуатации](operations.md), после проверки архива и остановки операций записи.
