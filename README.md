# Свои бумаги

Открытый сервис для самостоятельного учёта инвестиций по брокерским отчётам. Работает на вашем сервере или компьютере: загруженные файлы, журнал операций и база SQLite остаются в вашем хранилище. Один экземпляр рассчитан на одного владельца.

**Статус:** экспериментальная версия. Проверены отдельные варианты HTML-отчётов Сбера и XLS/XLSX-отчётов Альфа-Инвестиций. Перед использованием результата нужно сверить предпросмотр с итогами брокера и подтвердить полноту истории счёта. Сервис показывает причины, по которым расчёт недоступен.

## Что умеет

| Возможность | Как работает |
|---|---|
| Импорт отчётов | Сохраняет исходный файл и каждую разобранную строку; показывает сделки, деньги, позиции, остатки и неизвестные строки до подтверждения. |
| Проверка повторов | Сопоставляет операции из повторных и перекрывающихся отчётов. Неоднозначные совпадения требуют решения владельца. |
| Сверка | Сравнивает доступные позиции, денежные остатки и брокерские итоги с разобранными данными. Недостающие итоги помечает как `unavailable`. |
| Учёт и выгрузка | Ведёт журнал с привязкой к файлу и строке, считает FIFO и XIRR при достаточных данных, отдаёт операции, позиции, оценку, показатели и пробелы истории в CSV. |
| Сохранность | Доступ по паролю, резервная копия базы вместе с исходными файлами, проверяемое восстановление в новое хранилище. |

```text
отчёт → предпросмотр и сверка → подтверждение → журнал → расчёты и CSV
                     ↘ неизвестные строки и конфликты остаются видимыми
```

Сервис не торгует, не подключается к брокерским API и не рассчитывает налоговую декларацию. Котировки MOEX ISS отключены по умолчанию; для оценки можно указать собственную цену на дату. Подробнее о правилах учёта и границах расчётов — в [SPEC](docs/spec.md) и [контролях](docs/accounting-controls.md).

## Запуск за несколько минут

Нужны Docker с Compose и Python 3.12+ для интерактивного создания хеша пароля. Скопируйте проект и подготовьте окружение:

```bash
git clone https://github.com/abukreev-dev/svoibumagi.git
cd svoibumagi
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps -e .
.venv/bin/python -m svoibumagi hash-password
```

Последняя команда запрашивает пароль дважды и печатает только его `scrypt:` хеш. Создайте в корне проекта файл `.env` с таким содержимым, подставив свой хеш:

```dotenv
SVOIBUMAGI_PASSWORD_HASH=scrypt:...
SVOIBUMAGI_HOST_PORT=18080
```

```bash
chmod 600 .env
docker compose --env-file .env up -d --build
docker compose --env-file .env ps
```

Приложение слушает только `127.0.0.1:18080` на хосте. Для доступа с другого устройства настройте HTTPS-прокси на том же сервере. Cookie сеанса в основном режиме имеют флаг `Secure`, поэтому вход через обычный HTTP не сработает. **Готовый пример Nginx, локальный HTTP-режим, проверка запуска, резервные копии, восстановление и обновление** — в [инструкции по развёртыванию](docs/operations.md).

## Первый импорт

1. Откройте сайт через HTTPS, войдите по созданному паролю и добавьте счёт нужного брокера.
2. Загрузите отчёт. Проверьте номер счёта из файла, период, операции, конечные позиции и остатки, статусы сверки и неизвестные строки.
3. Подтвердите файл только после разбора предупреждений. Повторный отчёт можно загрузить для проверки: уже известные операции не должны появиться в журнале второй раз.
4. Загружайте историю начиная с открытия счёта. Пока она неполна, доходность и себестоимость могут оставаться недоступными. Отсутствие отчёта за месяц без операций требует отдельного подтверждения в интерфейсе при совпадающих граничных остатках.

Максимальный размер одного файла — 20 МБ. Поддержку конкретного варианта отчёта определяет предпросмотр и сверка, а не расширение файла. Текущее покрытие описано в [матрице форматов](docs/format-matrix.md).

## Разработка и участие

Исходники написаны на Python 3.12 с FastAPI и SQLite. Для проверки изменений:

```bash
.venv/bin/pytest -q
```

Добавляйте в тесты только синтетические отчёты. Настоящие брокерские файлы, базы, `.env`, пароли и ключи не должны попадать в Git или issue. Для нового формата нужны образец вне репозитория, независимые контроли сделок, позиций и денежных остатков, а также явная обработка неизвестных строк. Задачи и границы проекта: [PRD](docs/prd.md), [план работ](docs/backlog.md), [спринты](docs/sprints.md). Ход проверки реализации — в [журнале проекта](docs/progress.md).
