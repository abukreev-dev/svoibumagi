# Свои бумаги

Открытый веб-сервис для учёта инвестиций по брокерским отчётам Сбера и Альфа-Инвестиций. Рабочее название проекта; при необходимости его можно поменять без изменения требований.

## Состояние

Публичный лендинг и закрытый сервис размещены на `https://svoibumagi.bukreev.pro/` (исходный срез `90d077e`). Главная страница объясняет загрузку, сверку, расчёты, ограничения и хранение данных; владельцу доступен вход в закрытый обзор. На `ddl` проверены HTTPS, реальный вход, закрытость операций без сессии, пустая SQLite v20, резервная копия и пробное восстановление. Ночная копия настроена на сервере; внешнего хранения пока нет. [Инструкция по размещению](docs/deploy-ddl.md) и [акт приёмки](docs/release-acceptance.md) содержат детали. История и личные файлы в исходники и новый серверный том не копировались. Адаптеры ограничены проверенными вариантами HTML Сбера и XLS/XLSX Альфы; новые варианты и спорные строки требуют отдельной проверки.

Обзор и CSV проверены на двух синтетических счетах с оценённой и неоценённой позицией: известная часть показывается отдельно, общая оценка остаётся неполной. Пустой сервис явно пишет, что оценка недоступна, вместо нулевой стоимости портфеля. Нулевая позиция в иностранной валюте не требует конвертации и не блокирует расчёт; положительная позиция без конвертации по-прежнему недоступна. Прошли 180 синтетических тестов. Адаптеры принимают только проверенные варианты HTML Сбера и XLS/XLSX Альфы; неизвестные строки остаются в предпросмотре, полноценная финансовая история владельца будет загружена в пустой рабочий экземпляр.

Изолированная Docker-проверка через настоящий HTTP провела два контролируемых отчёта, по одному Сбера и Альфы: 62 события совпали с закрытыми контрольными таблицами; повторная загрузка не увеличила журнал. CSV открылись, резервная копия восстановила два счёта и 62 события, после перезапуска контейнера сохранились два исходных файла и журнал; SQLite прошла `quick_check` и проверку внешних ключей. Временный тестовый контейнер и том удалены, пустой рабочий том на порту 18081 сохранён. Это проверка согласованных образцов, а не полноты будущего личного портфеля.

Локальный рабочий Docker-экземпляр для новой загрузки полного пула доступен на `http://127.0.0.1:18081` с отдельным пустым постоянным томом; прежняя база `data/` остаётся проверочным снимком. Вход, сохранение синтетического счёта после перезапуска и возврат к пустой базе проверены. Локальный HTTP включён только дополнительным Compose-файлом при публикации порта на `127.0.0.1`; основной режим требует HTTPS. Приёмка механики сервиса опирается на старые и новые контрольные отчёты, а полнота и доходность личного портфеля будут проверяться после повторной загрузки всей истории. Разрывы нынешнего снимка не объявляются закрытыми. Поддерживаемые на уровне адаптеров варианты пока ограничены HTML Сбера и XLS/XLSX Альфы; неизвестные строки и недоступные сверки видны явно.

Кнопка удаления счёта показывается только при отсутствии любых связанных записей в текущей схеме SQLite. Счёт без известного номера, но с ожидающим файлом или ручной операцией, больше не выглядит пустым; сама база продолжает проверять запрет при удалении. Тестовый запуск ограничен каталогом `tests`, чтобы закрытый локальный релизный кандидат внутри `private/` не дублировал тесты. Прошли 175 синтетических тестов. Проверенные варианты файлов остаются HTML Сбера и XLS/XLSX Альфы; сквозная приёмка форматов не завершена.

Итоговая рублёвая оценка позиции на точную дату отчёта теперь читается из сохранённой исходной строки: у Сбера сумма рыночной стоимости и НКД, у Альфы итоговая стоимость позиции. Аудит исходных 128 уникальных файлов подтвердил наличие значений у всех 950 строк позиций; у Альфы сумма строк совпала с итогом раздела в 10 отчётах. В действующей базе все 35 ненулевых позиций последних пяти отчётов получили брокерскую стоимость, поэтому денежный остаток и конечная стоимость этих счетов известны без запроса котировок. На другие даты оценка по отчёту не переносится; ручная цена на ту же дату имеет приоритет. Полная доходность остаётся недоступной из-за истории, спорного договора и неразрешённых операций. Форматы HTML Сбера и XLS/XLSX Альфы всё ещё экспериментальные.

Обзор даёт закрытую CSV-выгрузку разрывов и подтверждений с номерами счетов. В текущей базе она показывает 25 ещё открытых интервалов и две отдельные записи владельца; статус `needs_owner_confirmation` означает совпадение граничных остатков и необходимость подтвердить отсутствие операций, а не доказанную полноту истории. Отозванные подтверждения остаются видимыми для аудита. Выгрузка не меняет журнал и не расширяет поддержку экспериментальных HTML Сбера и XLS/XLSX Альфы.

В текущем локальном рабочем каталоге приложение запущено на `http://127.0.0.1:18080` через `launchctl` с доступом только по loopback. Пароль создан для этого экземпляра и хранится в игнорируемом Git файле `private/local-app/login.txt` с правами владельца. Проверены HTTP-ответ страницы входа, реальный вход, обзор и история импорта из `data/`. Автоматические запросы MOEX ISS выключены. Этот локальный HTTP-запуск не заменяет проверку целевого HTTPS-хоста и Compose-тома.

Постоянная локальная база `data/` содержит 127 проведённых уникальных отчётов по пяти счетам. Спорный январский файл ИИС хранится только в закрытом реестре и исходном каталоге до установления принадлежности; его предварительная попытка и пустой шестой счёт удалены из рабочей базы после создания отдельной копии. Два подтверждённых владельцем месяца без операций сохранены для соответствующего счёта. Закрытая актуальная копия лежит вне Git в `private/owner-ledger-clean.zip`, версия до очистки — в `private/owner-ledger-before-quarantine-cleanup.zip`. Общий расчёт остаётся `unavailable`: другие календарные разрывы, спорная принадлежность договора и диагностические строки не разрешены. HTML Сбера и XLS/XLSX Альфы остаются экспериментальными форматами; полная приёмка импорта ещё не пройдена.

В полном временном совместном импорте 127 отчётов подтверждения владельца для октября 2025 и января 2026 применены к одному обычному счёту Сбера. Эти месяцы закрылись только для него, 1–2 ноября остались пробелом, разрывы остальных четырёх счетов не изменились. Резервная копия и восстановление сохранили обе записи; теперь тот же проверенный результат перенесён в `data/`.

Полный одноразовый совместный импорт провёл 127 уникальных отчётов в одной базе пяти счетов: 5194 наблюдения, 179 проверенных решений о перекрытиях и 4 решения по сделкам без номера. Конечные позиции и денежные остатки каждого счёта совпали с закрытыми контролями, четыре CSV-выгрузки сохранили исходные номера, резервная копия и восстановление прошли. Спорная январская копия ИИС из шестой группы осталась `awaiting_review`: межсчётный дубль заблокирован без изменения журнала. Общий расчёт остаётся `unavailable` из-за открытых вопросов истории и принадлежности договора. Форматы остаются HTML Сбера и XLS/XLSX Альфы, их сквозная приёмка ещё не завершена.

Отдельная временная SQLite-база объединила по одному проверенному отчёту пяти разных счетов Сбера и Альфы. Спорная копия отчёта ИИС для шестого счёта получила блокирующий межсчётный конфликт; журнал не изменился. Резервная копия и восстановление сохранили счета и события, общий расчёт остался `unavailable`. Это проверка совместной работы счетов, а не импорт всей истории в одну пользовательскую базу. На локальном Docker сейчас нет контейнера или постоянного тома «Своих бумаг»; запущены другие проекты. Поддерживаемые варианты отчётов остаются HTML Сбера и XLS/XLSX Альфы.

Актуальный Docker-образ со схемой SQLite v20 прошёл отдельный синтетический запуск: `/login` до и после перезапуска ответил HTTP 200, счёт с явными `RUB`/`active` сохранился, `quick_check` и внешние ключи без ошибок, `pip check` без конфликтов. Порт был назначен на loopback, после перезапуска его проверили заново. Временные контейнер, том и образ удалены; рабочий локальный Docker-проект и пользовательская база не менялись. Целевой HTTPS-хост ещё не проверен.

CSV оценки теперь отдельно показывает статус сверки отчёта, свежесть даты позиции и статус цены. При одновременных проблемах ни одна не скрывается общим `status`; пустой список проверок отчёта больше не считается совпадением в оценке и CSV позиций. Прошли 168 синтетических тестов. Поддерживаемые варианты отчётов остаются HTML Сбера и XLS/XLSX Альфы; сквозная приёмка реального портфеля ещё не завершена.

Закрытый контроль FIFO теперь включает частичную продажу первой партии из отчёта Альфы: исходные строки и время исполнения сверены отдельно, себестоимость проданной доли, комиссии и конечная партия совпали с расчётом. Вместе с прежним случаем Сбера прошли два контроля по реальным строкам. В выбранном отчёте Альфы нет отдельного итога реализованного результата брокера, поэтому сквозная приёмка чистого результата и XIRR остаётся открытой. Поддерживаемые на уровне адаптеров форматы не изменились: HTML Сбера и XLS/XLSX Альфы.

Проверка релизного архива сверяет и номера счетов из закрытого реестра: прежний архив выявил номер в README и журнале работ, после удаления этих упоминаний новые архивы проходят аудит. Точные номера остаются только в закрытых локальных файлах; wheel и исходный архив проверяются на известные номера из закрытого реестра. Из отслеживаемых файлов подготовлен отдельный локальный репозиторий `private/release-candidate-20261010` с одним начальным коммитом; состав и дерево сверяются с каждым новым срезом. Прежняя локальная история остаётся только в рабочем репозитории; кандидат не опубликован. Форматы HTML Сбера и XLS/XLSX Альфы остаются экспериментальными до приёмки.

Схема SQLite v20 явно хранит валюту счёта `RUB` и статус `active`; миграция прежней базы добавляет поля после резервного снимка. Другая валюта и неизвестный статус отклоняются ограничениями SQLite. Закрытие счёта через интерфейс пока не определено. Синтетическая миграция проверена, реальная пользовательская база не менялась. Поддерживаемые варианты отчётов остаются HTML Сбера и XLS/XLSX Альфы; общая история портфеля ещё не принята.

Создание резервной копии теперь проверяет `quick_check` и внешние ключи снимка SQLite до записи ZIP. Повреждённые ссылки дают отказ без архива; это проверено отдельным синтетическим случаем. Вместе с контролем SHA-256, размера и имени исходных файлов прошли 165 тестов и полный временный веб-прогон 128 отчётов с восстановлением всех шести групп. Реальная пользовательская база и целевой хост пока не проверялись.

Резервная копия теперь проверяет не только SHA-256 исходного отчёта, но и размер и каноническое имя файла для брокера; восстановление сверяет размер и имя с записью SQLite после проверки содержимого архива. Архив с подменённым размером в базе отклоняется без создания целевого каталога. Проверены 164 синтетических теста и полный временный веб-прогон 128 уникальных отчётов с резервной копией и восстановлением каждой из шести групп. Поддержка импорта и финансовые итоги реального портфеля остаются экспериментальными.

Текущий Docker-образ повторно проверен на изолированном синтетическом томе: `/login` ответил до и после перезапуска, счёт сохранился, SQLite v19 прошла `quick_check` и `foreign_key_check`, `pip check` не нашёл конфликтов. Пробный контейнер публиковал порт только на `127.0.0.1`; контейнер, том и образ после проверки удалены. При назначении случайного хостового порта Docker может выбрать другой порт после перезапуска, поэтому проверка читала его заново из `docker inspect`. Это локальная проверка, а не приёмка выбранного HTTPS-хоста или пользовательской базы.

Проверка граничных остатков для периода без операций требует явные позиции с ISIN и валютой в обоих соседних отчётах. Отсутствующая таблица позиций, строка без ISIN или смена валюты при том же ISIN оставляет разрыв открытым даже при подтверждении владельца; пустые денежные валюты тоже не пропускаются. Синтетические отрицательные случаи и полный временный прогон 128 отчётов с двумя подтверждёнными месяцами прошли. Остальные разрывы и полная доходность реального портфеля остаются неподтверждёнными.

Для подтверждения периода без операций обзор теперь показывает точные незакрытые даты рядом с каждым счётом и отдельную форму для каждого подходящего разрыва. Форма появляется только при совпадающих граничных остатках и отсутствии известных либо неразобранных движений внутри разрыва; существующее действующее подтверждение не предлагается повторно. Совпадение остатков не заменяет подтверждение владельца. 162 синтетических теста и полный временный веб-прогон 128 отчётов с двумя уже подтверждёнными месяцами прошли; формат импорта остаётся экспериментальным.

Полный одноразовый веб-прогон 128 уникальных отчётов теперь дополнительно сверяет номер счёта из каждого предпросмотра с проведённым локальным счётом, четырьмя CSV-выгрузками и восстановленной копией. Все шесть групп прошли; это подтверждает перенос номера для текущих образцов, но не принадлежность спорной пары ИИС и не полноту календарной истории. Отдельный закрытый прогон двух подтверждённых владельцем месяцев также прошёл: октябрь закрывается только до 31 числа, 1–2 ноября остаются пробелом, январь закрывается полностью.

[Матрица форматов](docs/format-matrix.md) пересчитана по текущим 128 уникальным отчётам. В ней отдельно указаны автоматические совпадения и недоступные проверки; HTML Сбера и XLS/XLSX Альфы остаются экспериментальными вариантами до сквозной приёмки. Прямой поиск другого отчёта той же группы с явной позицией на совпадающую конечную дату не подтвердил ни один из 110 случаев отсутствующей позиции. Два случая имеют нулевой начальный остаток на следующий день в другом отчёте, но отчётный статус остаётся `unavailable` до согласованной сквозной методики.

Обзор и четыре CSV-выгрузки показывают номер договора/счёта, извлечённый из проведённых отчётов, отдельным полем `account_number`. Локальное название сохраняется для различения записей. Пока отчёт не проведён, номер неизвестен; если проведённые источники противоречат друг другу, обзор помечает неоднозначность, CSV оставляет номер пустым, а подтверждённые FIFO/XIRR блокируются. Известные деньги и оценка по последнему отчёту остаются видны как неполные. Проверены 161 синтетический тест, полный одноразовый веб-прогон 128 уникальных отчётов и состав локальных wheel и исходного архива. По одному обычному счёту Сбера октябрь 2025 и январь 2026 подтверждены владельцем как месяцы без операций, за которые Сбер не формирует отчёты; подтверждения проверены только в одноразовой базе, постоянная пользовательская база не менялась. Другие календарные разрывы остаются открытыми.

SB-22 реализован на локальной схеме SQLite v19: владелец может записать и отозвать точный период без операций. Расчёт закрывает такой пробел только при совпадении позиций и денег на границах соседних отчётов, отсутствии проведённых операций и неразрешённых строк. Частично подтверждённый интервал оставляет остальные даты открытыми; новая противоречащая операция блокирует проверенный результат. Неразрешённая строка соседнего отчёта блокирует именно тот промежуток, на который могла прийтись её операция; строки с известной датой вне промежутка остаются отдельной диагностикой. 159 синтетических тестов и закрытый веб-прогон прежних 118 уникальных отчётов прошли. Локальные wheel и исходный архив прошли аудит состава (29 и 97 файлов); установленный отдельно wheel создал SQLite v19, сохранил подтверждение и открыл `/login`. Отдельный Compose-проект v19 сохранил после перезапуска синтетические счёт, денежное событие и подтверждение периода; `/login` ответил HTTP 200, SQLite прошла `quick_check` и проверку внешних ключей, порт остался на loopback, временный том удалён. Два подтверждённых владельцем месяца сохранены в закрытой заметке; в пользовательскую базу они не вносились. Безопасность веб-маршрутов проверяется синтетическим регрессионным сценарием: каждый приватный GET и POST без сессии возвращает 401, а каждый изменяющий POST с сессией и неверным CSRF возвращает 403. Проверка охватывает текущий список маршрутов, включая загрузку, исходные файлы, CSV и резервную копию; она не заменяет проверку выбранного HTTPS-хоста перед релизом. Журнал операций теперь фильтруется по счёту, типу события, источнику, датам операции и названию/ISIN/номеру сделки. Он показывает число найденных записей и сохраняет выбор в форме. История загрузок доступна отдельной закрытой страницей `/imports` с фильтром по счёту и страницами по 50 попыток. Главная показывает 30 последних и ссылку на полный список. Синтетический сценарий проверил переход к попытке за пределами главной страницы, переход между страницами и отказ для неверного номера страницы; неподдерживаемые варианты отчётов не считаются подтверждёнными из-за этой функции.

Текущий wheel дополнительно установлен в отдельный временный каталог: из установленного пакета открылись `/login` и новая история загрузок, без сессии история вернула 401, новая SQLite прошла `quick_check`. Целевой HTTPS-хост и пользовательская база этой пробой не проверялись.

В закрытом реестре теперь 129 физических файлов, 128 уникальных: новые файлы не содержат неизвестных строк, а все доступные сверки парсера совпали. Карта периодов сократилась с 38 до 26 разрывов; во всех оставшихся позиционные и денежные остатки на границах совпадают. Закрытая HTML-карта показывает номера договоров/счетов из содержимого файлов, проверенные по SHA-256 и ключу группы, отдельно от типа обычный/ИИС. Владелец подтвердил отсутствие операций в октябре 2025 и январе 2026 для одного обычного счёта; Сбер не формирует отчёт за месяц без операций. Эти месяцы не требуют выгрузки. Ранее принятые 118 уникальных источников повторно прошли закрытые контроли. Десять новых файлов получили независимые экономические контроли из исходных HTML: 75 сделок, 70 позиций, 100 денежных компонентов и 10 остатков совпали с импортом. Расширенный временный веб-прогон 128 уникальных отчётов дал 179 решений о перекрытиях и 588 межотчётных проверок без расхождений. Сквозная история и реальные показатели портфеля остаются неподтверждёнными из-за остальных открытых вопросов.

Каркас и локальный запуск (SB-03) проверены на Docker-образе со схемой v18: синтетический счёт пережил перезапуск отдельного контейнера и тома, `/login` ответил HTTP 200, SQLite прошла `quick_check` и проверку внешних ключей. Полный сценарий со счётом, ручным событием и файлом ранее прошёл в изолированном Compose-проекте на схеме v17 с публикацией порта только на `127.0.0.1`. Пароль передавался приватной переменной окружения. Пользовательская база и целевой HTTPS-хост ещё не проходили релизную проверку.

Адаптер Сбера v7 сохраняет исходные строки операций, 853 строки справочника, 648 структурных строк и 853 строки брокерских итогов/сводки. Все 4590 непустых строк распознанных таблиц 109 HTML имеют явную классификацию; 4310 значений итогов совпали с деталями в независимом аудите. Предпросмотр отделяет справочник, структуру и проверенные итоги от операций. Поддержка HTML Сбера и XLS/XLSX Альфы остаётся экспериментальной из-за других открытых ограничений. В исходном наборе до октябрьских загрузок было 38 интервалов без отчёта; пользователь пояснил, что в месяц без операций отчёт мог не формироваться. Это не доказывает ни наличие, ни отсутствие операций внутри интервала, поэтому полная история и XIRR по этим файлам не подтверждены. Для новых файлов выполняется отдельная независимая приёмка.

Закрытый аудит договоров Сбера выявил один код и в обычном отчёте, и в отчёте ИИС; при этом два отчёта ИИС с разными кодами имеют одинаковое экономическое содержимое. Владелец подтвердил, что ИИС не переоформлялся. Причина совпадения и принадлежность спорных файлов пока не установлены; источники остаются в раздельных группах. Это ограничение не влияет на синтетические тесты, но не позволяет принять общий реальный портфель.

Оба адаптера отвергают отчётный период с окончанием раньше начала. Синтетическая загрузка такого HTML не оставляет попытку или копию файла; 140 тестов и полный временный веб-прогон 118 уникальных образцов прошли. Новые варианты отчётов по-прежнему требуют отдельной проверки.

Адаптер Альфы v12 сохраняет и классифицирует все 4845 непустых строк пяти распознанных листов 10 XLS/XLSX, включая реквизиты, продолжения позиций, сноски, денежные и портфельные итоги, налоговую сводку и метаданные неторгового раздела. 99 значений дополнительных итогов совпали с исходными деталями; налоговая проверка доказывает только равенство трёх чисел. Для 1415 распознанных сделок время заключения сверено с исходными ячейками и используется в FIFO после даты заключения и расчёта; внутри одной даты исходные строки текущих образцов уже идут по времени, поэтому проверенные экономические итоги не изменились. Неизвестные строки будущих вариантов сохраняются с адресом и причиной. Ожидающие загрузки прежней версии адаптера нужно загрузить заново.

Загрузка XLSX проверяет распакованный размер и число ZIP-записей, XLS/XLSX ограничены миллионом ячеек. Синтетические превышения отклоняются с причиной; все 10 доступных файлов Альфы прошли повторный веб-прогон. Это не подтверждает будущие варианты формата.

Точные финансовые суммы из реальных брокерских отчётов остаются только в игнорируемых Git закрытых контролях; публичные описания прогресса сообщают результат сверки без этих сумм. Для воспроизводимых тестов в репозитории используются синтетические значения.

Расчётный слой отклоняет `NaN` и бесконечные значения в сделках, начальных партиях, переводах и возврате тела облигации до изменения партий. Проверка порядка погашений теперь заранее охватывает все бумаги в один день: сделка по второй бумаге не может скрыться после обработки первого действия. Синтетический контроль двух разных счетов на одну дату сверяет с расчётом вручную остатки, FIFO, XIRR, обзор и CSV. 150 синтетических тестов, независимый закрытый FIFO-контроль и повторный веб-прогон всех 118 уникальных отчётов прошли. Другие варианты отчётов, амортизация по реальному подтверждённому примеру и полная история счетов остаются неподтверждёнными.

Повтор ручной корректировки с той же причиной теперь сравнивается по экономическим полям: `100` и `100.00` считаются одной суммой, смена отображаемого названия бумаги при том же ISIN не создаёт вторую сделку. Проверка выполняется в сериализованной транзакции. Канонизация десятичных значений для ключей событий больше не округляет числа длиннее точности текущего контекста `Decimal`. Синтетические проверки и полный закрытый веб-прогон 118 отчётов прошли; существующие записи базы не переписывались.

Оценка и CSV не записывают остаток или стоимость позиции в поле «рубли», если отчёт помечает их другой валютой и подтверждённой конвертации нет. Позиция остаётся видимой со статусом необходимости конвертации; известные рублёвые позиции дают отдельный неполный итог. Проверены синтетические валютные случаи и полный закрытый прогон текущих образцов. Валютные варианты отчётов V1 не поддерживаются.

Общий XIRR рассчитывается отдельно от индивидуальных XIRR: отсутствие цены на дату перевода бумаги между своими счетами блокирует доходность каждого счёта, но не общий внешний поток при полной истории и конечной оценке на одну дату. Синтетический сквозной сценарий с таким переводом прошёл; реальные счета по-прежнему не имеют подтверждённой полной истории.

Подтверждение импорта отклоняет операцию, если её строка отсутствует среди сохранённых строк этой попытки или имеет несовместимый класс. Схема v15 также отклоняет новые события и наблюдения без сохранённой исходной строки, запрещает изменять связанную строку и удалять её последнюю подходящую копию. Отказ атомарен: журнал не меняется. Синтетические отрицательные случаи и повторный веб-прогон всех 118 уникальных отчётов прошли; SQL-аудит шести временных баз подтвердил ссылки проведённых операций и наблюдений. Записи, созданные до v15 без сохранённых строк, остаются в базе и требуют отдельной проверки происхождения.

При чтении журнала каждая брокерская операция получает признак наличия строки подходящего класса в **проведённой** попытке импорта. Если у старой операции такой строки нет, журнал показывает её адрес и предупреждение, а CSV операций — `source_row_status=missing`. Подтверждённые FIFO и XIRR по счёту недоступны с явной причиной; известные денежный остаток и оценка по отчёту остаются видимыми. Команда `.venv/bin/python scripts/audit_source_provenance.py /путь/к/ledger.sqlite3` открывает существующую базу v18 или v19 только для чтения, проверяет исходные строки операций и наблюдений, расположение, размер и SHA-256 связанных файлов, повторную привязку договора к счетам одного брокера и типа и противоречащие номера в проведённых отчётах одного локального счёта. Она выдаёт только числовые ID проблем. Код возврата 1 означает неполный аудит, 2 — невозможность аудита. Синтетические проверки миграции, расчёта и отображения прошли; исходные строки старых записей автоматически не восстанавливаются.

Для релизной проверки добавлен `scripts/audit_dependency_licenses.py`: он сверяет все 22 закреплённые зависимости с lock-файлом, рассмотренными декларациями лицензий и установленными лицензионными файлами. Проверка прошла локально и внутри Docker-образа без сети; подмена версии в копии lock-файла была отклонена. Это технический контроль состава, а не подтверждение права на публикацию.

Локальная проверка релизных архивов теперь читает содержимое файлов wheel и исходного архива: ищет известные отпечатки и имена закрытых отчётов из игнорируемого реестра, ключи счетов и типовые признаки персональных данных, не печатая найденные значения. В текущей сборке проверены 29 файлов wheel и 96 файлов исходного архива, совпадений нет; синтетические тесты подтверждают срабатывание в файлах без расширения и метаданных. Это выборочный контроль утечки, а не разрешение на публикацию. HTML Сбера и XLS/XLSX Альфы остаются экспериментальными; иные варианты форматов не проверены.

Тот же аудитор требует GPL/SPDX-маркер в каждом Python-файле пакетов, лицензионное выражение `GPL-3.0-or-later` в метаданных и текст GPLv3 в архиве. Актуальные локальные wheel и исходный архив прошли эти проверки. Правообладатель и окончательные уведомления для выбранного способа распространения не утверждены.

Проверка лицензий зависимостей относится к версиям из `requirements.lock`. Для установки wheel с этим набором сначала установите lock-файл, затем wheel с `--no-deps` по [инструкции](docs/operations.md). Прямая установка wheel может выбрать другие версии по диапазонам метаданных и требует отдельной проверки.

При отдельном дневном списании комиссии без связи со сделкой себестоимость партий FIFO и реализованный результат недоступны: денежный остаток включает плату, но её разбивка по сделкам не подтверждена. XIRR может рассчитываться отдельно, если вся история денежных потоков, конечный остаток и цена подтверждены: комиссия уже уменьшает денежный остаток. Это проверено синтетически; соответствующий вариант Альфы пока не принят как полностью поддержанный.

Поиск XIRR проверяет единственность корня на поддерживаемом диапазоне ставок. Синтетические контрольные потоки с тремя корнями, с кратным корнем, с близким к нулю минимумом без корня и с единственным корнем при нескольких сменах знака проходят ожидаемые проверки. Численно неразличимое касание нуля даёт статус недоступного расчёта. Реальный XIRR по имеющимся неполным историям счетов пока недоступен.

Дополнительный закрытый контроль FIFO на вручную сверенном отчёте ИИС Сбера подтвердил результат продажи и себестоимость новых партий с учётом комиссий. Точные значения сохранены только в закрытом контроле. Брокерский налоговый результат отсутствует, поэтому сравнение с ним не заявляется.

Общий числовой парсер Сбера и Альфы отклоняет `NaN` и бесконечность как нечисловые финансовые значения. Синтетический HTML с таким денежным остатком оставляет строку явной диагностикой; повторная закрытая проверка 118 реальных контрольных отчётов прошла без изменений результатов.

При получении котировок ISS нечисловое количество сделок также даёт штатный статус недоступной цены. Такая котировка не записывается в базу.

Итоговая себестоимость и реализованный результат показываются в интерфейсе и CSV с точностью до копейки. Частичное распределение себестоимости остаётся в `Decimal` без промежуточного округления, чтобы повторные продажи не теряли доли стоимости партии.

CSV расчётов сохраняет указанный в отчёте остаток денег и оценку бумаг отдельного счёта при недоступном XIRR, указывая причину неполноты; неизвестные суммы остаются пустыми. Общая строка не складывает счета с неподтверждённым общим итогом.

Текстовые поля CSV защищены от начала формулы, включая полноширинные знаки и управляющие символы перед ней; синтетические примеры проверены. После редактирования и повторного сохранения CSV в табличной программе результат нужно проверять отдельно.

Для одного дополнительного XLS Альфы закрытые агрегатный и независимый построчный контроли отдельно сверили исходные 41 сделку, 79 денежных строк, комиссии, количества и остатки с адаптером. Построчный контроль извлечён из колонок источника после ручной проверки секций и итогов; полностью вручную набранной таблицы для этого файла пока нет.

Независимый аудит всех десяти файлов Альфы дополнительно сверяет по исходным подписям категории 2 690 денежных строк; синтетическая подмена категории при прежней сумме отклоняется. Неизвестный источник поступления с субсчёта сохраняет предупреждение.

Пятнадцатый ручной контроль Сбера сверил продажу и покупку в одном расчётном дне: обе суммы в общей денежной строке, комиссии по сделкам и денежным списаниям, изменения двух позиций и итоговый остаток сошлись с HTML. Полная история счетов при этом не подтверждена.

Ещё два однодневных отчёта Сбера вручную сверены по дивидендам и удержанному налогу; в одном дополнительно проверено отдельное внешнее пополнение. Проведённые и плановые позиции не смешались. На этом этапе ручной контроль был у 17 из 118 уникальных отчётов.

Следующий ручной контроль Сбера сверил день с несколькими продажами, покупками и выводом денег. НКД, комиссии, позиции и остаток сошлись; отдельный синтетический расчёт подтвердил, что вывод является внешним потоком XIRR, а денежный расчёт сделки — нет. Затем вручную сверены однодневная покупка девяти акций, месячный отчёт с двумя купонами и двумя покупками, покупка облигаций с НКД и пополнением, два дня без проведённых сделок, первые доступные месячные отчёты ИИС и обычного счёта, цепочка 5–8 апреля с плановыми и проведёнными покупками и три месячных отчёта ИИС с купоном и облигацией. На этом этапе контролировались 32 из 118 отчётов.

Временная база удалена; это локальный контроль конкретной последовательности.

Независимый аудит 108 уникальных HTML Сбера дополнительно сравнил комиссии сделок с отдельными денежными списаниями: брокерская и биржевая суммы сошлись на всех 77 датах расчётов. Десятый ручной контроль сверил короткий месячный HTML Сбера. Выплаченный купон и подписанное сальдо НКД теперь показаны отдельно; их сумма даёт денежный показатель купона с учётом НКД. FIFO использует чистую сумму сделки, XIRR — полный денежный поток и грязную цену облигации. Налоговая база не вычисляется; старые сделки Сбера без проверенного поля НКД остаются `unavailable`. Эти правила проверены синтетическим примером с купоном и грязной ценой, тестом старой записи и закрытым контрольным HTML; полный финансовый итог по реальной истории пока не принят.

Лицензии 22 закреплённых зависимостей проверены. Wheel v18 установлен в отдельный временный каталог, создал исправную SQLite v18 и открыл `/login`. - Форматы отчётов: обнаружены HTML Сбера и XLS/XLSX Альфы. Ни один вариант пока не получил статус полной поддержки V1; требуется доказать полную сверку на согласованном наборе образцов, включая позиции, отсутствующие в итоговой таблице, и налоговые детали выплат. У остальных 30 крайние остатки совпали; состав операций внутри всех разрывов остаётся неизвестным. Приоритетные восемь интервалов с соседними файлами перечислены в закрытой `private/gap-boundary-review.md`. Самый ранний нулевой остаток не подтверждает дату открытия, а отсутствие отчёта за разрыв не доказывает отсутствие операций. Без независимого подтверждения смысла разрывов полная история и XIRR недоступны. При подтверждённой полной истории расчёт счёта может отдельно вывести нулевой остаток проданной бумаги, отсутствующей в итоговой таблице; исходная проверка отчёта остаётся `unavailable`. В длинном образце Альфы обнаружены продажи до покупок внутри одной даты расчёта; время заключения сделок подтверждает этот порядок в проверенном случае. Короткие позиции вне V1, поэтому FIFO явно блокируется. Ручная амортизация и погашение связаны с конкретной денежной строкой и проверены на синтетике; автоматическое распознавание брокерских действий не реализовано; перенос партий доступен через ручной парный перевод, но на реальных итогах не принят. Валютная конвертация не реализована. Котировка ISS пока покрывает только акцию TQBR с введённым SECID: последняя сделка и историческое закрытие `CLOSE` на выбранную дату. Обе ветки проверены на SBER через локальный HTTPS-прокси; прямой локальный запрос завершился таймаутом, облигации TQOB/TQCB проверены на двух отдельных примерах, а остальные бумаги требуют отдельной проверки или ручной цены. Цена старше семи календарных дней не используется в оценке. Результат для счёта с неизвестной историей, неподтверждённой сверкой или нерублёвыми операциями показывается как недоступный.

Текущая схема SQLite v19. Один подтверждённый договор нельзя вновь привязать ко второму локальному счёту того же брокера и типа: предпросмотр показывает блокировку, подтверждение откатывается, SQLite отклоняет новую привязку. Разные типы счёта не объединяются автоматически; уже существующие одинаковые привязки миграция сохраняет для ручного разбора. Новые брокерские события и наблюдения должны ссылаться на сохранённую строку источника подходящего класса в **подтверждённой** попытке импорта; связанную строку нельзя изменить или удалить без замены. Подтверждение переводит попытку в `committed` и записывает события одной транзакцией, ошибка откатывает оба изменения. Миграции v16→v17 и v17→v18 создают предварительную копию. Исторические события с неполным происхождением не удаляются автоматически и требуют отдельного аудита; пользовательская база не обновлялась.

Неподтверждённую или отклонённую загрузку можно удалить на её странице. Удаляются попытка, исходные строки и решения; файл удаляется только после последней ссылки на него. Проведённый импорт защищён от удаления. Синтетические проверки охватывают общий файл двух попыток и двух счетов, отказ для проведённого импорта, доступ через вход/CSRF и откат нового файла при ошибке записи исходных строк.

Адаптер Сбера отклоняет HTML с несколькими таблицами одной обязательной секции вместо молчаливого выбора последней. После изменения повторно разобраны все 109 распознанных образцов Сбера; числа сделок и исходных денежных строк тогда не изменились. В шести строках дивидендов Сбера отчёт указывает сумму до удержания, количество и ставку; теперь сумма до удержания и вычисленная разница с чистым зачислением проводятся отдельными связанными событиями. Для седьмой выплаты сумма до удержания отсутствует, поэтому налог остаётся непроверенным.

Независимый просмотр исходных таблиц нашёл 89 ранее пропущенных строк позиций Сбера: у бумаги было числовое название и корректный ISIN. Ошибка исправлена; в 109 отчётах теперь распознано 848 позиций вместо 759, 15 проверок стали `matched`, новых расхождений нет. Отдельные повторяемые проверки адресов охватили 2236 значимых строк Сбера и 4229 Альфы без пропусков по заданным сигнатурам. Это доказывает обнаружение строк, но не заменяет ручную проверку всех чисел. Отдельное чтение исходных ячеек сверило числовые поля и даты 616 строк сделок Сбера (включая 4 агрегата), 1415 сделок Альфы, 848 и 45 строк позиций, 109 и 10 денежных остатков, 334 движения Сбера и 2690 исходных денежных строк Альфы без расхождений. Закрытый результат — `private/report-value-audit.json`; контрольные изменения суммы сделки в памяти для обоих брокеров аудит отверг. Совпадение чтения ячеек с адаптером не подтверждает экономическую классификацию или недостающие периоды.

В версии v3 адаптер Сбера начал отдельно сохранять 853 служебные строки справочника бумаг, используемые для сопоставления кода и ISIN. Ручная амортизация и погашение облигации теперь связываются с конкретной положительной денежной строкой того же счёта и даты. Отдельное действие с причиной меняет себестоимость партий и при погашении закрывает количество; выплата не записывается повторно. FIFO, промежуточные позиции, журнал, CSV, веб-форма и резервная копия проверены на синтетическом сценарии; отсутствие связанного действия или неоднозначный порядок в день сделки блокируют проверенный результат. Ручной перевод бумаги между своими счетами связан парой строк в журнале; исходная дата покупки и себестоимость партий сохраняются. Синтетический сценарий проверил FIFO, XIRR двух счетов и общего портфеля, CSV, веб-форму, копию и отказы при недостатке партий/цены. Автоматический разбор перевода и амортизации из брокерских отчётов остаётся открытым: в найденных образцах нет подтверждённых строк и итогов для этих случаев.

Резервная копия теперь создаётся только при совпадении каждого исходного файла с SHA-256 в журнале. Перед записью архива исходные файлы копируются во временный снимок и повторно сверяются с копией базы; внешнее изменение оригинала во время записи архива не создаёт несогласованную копию. Восстановление проверяет эту связь отдельно от ZIP-манифеста; архив с изменённым файлом или неподдерживаемой схемой не оставляет целевого каталога. Синтетические отрицательные проверки и прежняя проба успешного восстановления пройдены.

Для сделки Сбера без номера добавлен выбор: оставить исходную строку контролем или провести её целиком как агрегат с причиной. Расчётный срез теперь снимает предупреждение об агрегате лишь после проверки решения и соответствующих событий журнала; четыре строки разрешены в закрытом прогоне, первоначальные строки предпросмотра сохранены. При временном импорте с обоими манифестами все 510 межотчётных сравнений сошлись; пользовательская база не изменялась. Это не закрывает пробелы истории и остальные барьеры приёмки.

Фактический HTTPS-ответ ISS для акции TQBR не содержит `LASTTRADEDATE`. По [руководству ISS](https://www.moex.com/files/4gspnsx9er8s7wg65ve3ccg1ch) параметр `iss.only` ограничивает блоки ответа; исправленный запрос явно включает `dataversion` наряду с `securities` и `marketdata`. Адаптер проверяет дату торгов по `dataversion`, положительное число сделок, дату обновления рынка и отсутствие будущей даты относительно Москвы; синтетические тесты проверяют также состав запроса и границу даты. Прямой запрос из локальной среды завершается сетевым таймаутом. Через локальный HTTPS-прокси штатная функция успешно получила и разобрала реальный ответ по акции SBER/`RU0009029540` 9 октября 2026 года на хосте и в Docker-образе v12; Compose теперь принимает необязательный адрес исходящего прокси из приватного `.env`. Доступность на другом хосте и остальные бумаги требуют отдельной проверки. Используется [официальный интерфейс ISS](https://www.moex.com/a2920).

В обзоре добавлено обновление котировок всех ненулевых позиций на выбранную дату. Сервис проверяет весь набор ответов ISS по ISIN до записи, затем сохраняет цены одной транзакцией. Ошибка одной бумаги оставляет сохранённые цены без изменений; повтор с теми же значениями не создаёт дублей. Синтетические тесты проверили откат при ошибке записи второй бумаги, недоступный ответ и повторный запрос. Итоги портфеля всё ещё требуют сверки с брокерскими отчётами.

Wheel v18 установлен в изолированный временный каталог: приложение из установленного пакета создало SQLite v18 с `quick_check=ok`, без ошибок внешних ключей, и открыло `/login` с HTTP 200. Отдельный Compose-проект v18 на свободном хостовом порту `18080` сохранил синтетические счёт, ручное событие, проведённый отчёт и исходный файл после перезапуска; резервная копия восстановила их в новый каталог. Хостовый порт опубликован только на loopback. Целевой HTTPS-хост и пользовательская база не затрагивались.

Отдельный закрытый веб-прогон провёл через обычные маршруты все 118 уникальных отчётов в шести изолированных группах договоров: 5039 наблюдений событий, 123 проверенных решения по перекрытиям и четыре решения по сделкам без номера. Скачивание исходника прошло; CSV операций сверены по числу событий и SHA источников, CSV позиций и оценки — по количествам последних контрольных отчётов, CSV расчётов — по конечным денежным остаткам. Временные базы удалены. Это техническая проверка доступных файлов, без признания полной истории или принадлежности двух договоров ИИС.

После полного веб-прогона каждая из шести временных баз дополнительно сохранена в закрытый архив и восстановлена в новый каталог. Числа отчётов и событий, SHA исходников и конечные позиции совпали с исходной временной базой и контролем брокера; все временные архивы и базы удалены.

После прежней миграции схемы Docker-образ v15 был проверен в одноразовом контейнере: `/login` ответил HTTP 200, SQLite прошла `quick_check` и проверку внешних ключей. Отдельный синтетический Docker-том перешёл с v14 на v15 с сохранением ручного события и предварительной копией. Контейнеры, том и метка образа удалены; целевой HTTPS-хост не проверялся.

Синтетический отрицательный веб-сценарий проверяет отказ провести отчёт с неизвестной строкой без объяснения или при неверном CSRF, отклонение загрузки, пустой журнал после отказов и отсутствие дубля при повторной загрузке после явного решения. Предпросмотр показывает источник, повтор и расхождение денег `difference`. Локальные критерии веб-сценария и защиты доступа SB-14/SB-13 проверены; приёмка реальных счетов, расчётов и HTTPS-хоста остаётся отдельной.

## Следующий барьер приёмки

Установить принадлежность групп счетов и сохранить 38 разрывов периодов как неполную историю, пока их смысл не подтверждён другим источником. Для работы создана закрытая очередь `private/acceptance-review.html`: 118 уникальных отчётов из 119 файлов (один файл Сбера продублирован), 0 без экономического контроля, 3 с диагностическими строками и 11 с недоступными проверками. Очередь повторно сверяет все закрытые экономические контроли с исходниками перед показом статуса. Один отчёт контролируется через полное совпадение HTML с уже проверенным отчётом после нормализации только кода договора; принадлежность договоров этим не установлена. Найденные вспомогательные выгрузки операций Сбера за январь 2025 года и портфеля Альфы за январь–июнь 2025 года не охватывают пропущенные даты. Просмотр трёх портфелей Сбера в InteliInvest 10 октября 2026 года подтвердил наличие записей до февраля или мая 2026 года, но не полноту истории; закрытая заметка — `private/intelinvest-review.md`. До завершения приёмки полный импорт и XIRR по предоставленным данным не объявляются проверенными. Реальные отчёты, базы, ключи и пароли остаются вне репозитория.

Среди январских отчётов ИИС найдена пара с разными кодами договора, но одинаковыми сделками, позициями и денежными строками. Предпросмотр второй копии тех же сделок на другом счёте показывает блокирующий конфликт и скрывает подтверждение; прямое подтверждение откатывается. Синтетический тест проверил это поведение. Независимый аудит всех 118 уникальных файлов нашёл ровно одну пару с полностью одинаковым экономическим содержимым при разных договорах; это именно указанная пара ИИС. Повторный технический прогон внутри групп договоров дал 123 спорные пары, 4 разрешённые в техническом расчётном срезе безномерные сделки и 510 межотчётных проверок без расхождений; эти проверки не включают междоговорную пару. Принадлежность договоров остаётся неразрешённой, поэтому оба отчёта нельзя складывать в общий портфель. Детали пары хранятся только в `private/account-identity-review.md`. Отдельно сверены 12 сделок, 8 позиций и 5 денежных строк февральского отчёта Сбера за 2026 год; тикер одной сделки сопоставлен с ISIN по таблице инструментов источника. Ещё один мартовский отчёт Сбера прошёл проверку 15 сделок, 12 позиций, 4 денежных строк и итогового остатка; одна сделка с расчётом после конца периода осталась исключённой. Однодневный отчёт Сбера за март 2025 года добавлен в контроль: его 15 сделок, 12 позиций и 3 денежные строки совпали с проверенным месячным отчётом, где отдельно есть ещё одно пополнение. Июльский отчёт Сбера за 2025 год проверен по 39 сделкам, 3 позициям, 12 денежным строкам и остатку; денежные движения дают точное изменение остатка. Четвёртая проверка позиции осталась `unavailable`: инструмент отсутствует в итоговой таблице отчёта. Однодневный январский отчёт Сбера проверен по 30 исполненным сделкам, 17 позициям, 3 денежным строкам и остатку. Шесть сделок с расчётом на следующий день остались исключёнными из проведённого среза. Два январских дневных отчёта Сбера дополнительно сверены: в каждом 38 сделок; проверены 22 и 20 позиций, три и четыре денежных строки, а также итоговые остатки. В отчёте за 29 января вывод средств отделён от расчёта по сделкам. Февральский отчёт Сбера за 2025 год сверён по 57 сделкам, 20 позициям, 7 денежным строкам и остатку. Ещё четыре проверки позиции остаются `unavailable`: соответствующие бумаги отсутствуют в итоговой таблице источника. Месячный январский отчёт Сбера дополнительно сверен по 118 сделкам, 22 позициям, 18 денежным строкам и остатку. Все сделки и денежные строки из трёх проверенных дневных отчётов 14, 27 и 29 января совпали с соответствующими строками месячного отчёта. Декабрьский XLS Альфы за 2025 год прошёл построчную сверку 41 сделки, 79 денежных строк, 4 позиций, остатка и итога банковских комиссий; две проверки позиции остались `unavailable`, потому что бумаги отсутствуют в итоговой таблице. Оба отчёта Альфы за февраль 2026 года (XLS и XLSX) по отдельности сверены по 135 сделкам, 181 денежной строке, 6 позициям, остатку и комиссии; 19 незавершённых сделок каждого файла исключены. Их экономические контроли совпали после десятичной нормализации значений. Два длинных XLS Альфы отдельно сверены по 388/504 сделкам, 799/1023 денежным компонентам, остаткам и итогам; более короткий период входит в годовой по операциям. Теперь все 118 уникальных отчётов имеют закрытый экономический контроль: 117 по исходным ячейкам напрямую и один через проверенную идентичность HTML после замены кода договора.

В интерфейсе Intelinvest дополнительно проверены пять из восьми приоритетных разрывов между отчётами Сбера: в одноимённых портфелях операций внутри интервалов не видно. Исполнение и полнота операций за эти даты остаются неподтверждёнными. Детали — в закрытых `private/intelinvest-review.md` и `private/gap-boundary-review.md`. ## Цель первой версии

Один пользователь, загрузка файлов вручную, предварительный просмотр и подтверждение импорта, защита от дублей, сверка позиций и денежных остатков, общая картина по счетам, FIFO и XIRR, экспорт и резервное копирование. Предполагаемый стек: Python, FastAPI, SQLite, серверные HTML-шаблоны, Docker Compose. Цели и критерии приёмки находятся в PRD, технические правила — в SPEC, проверяемые задачи — в ТЗ.
